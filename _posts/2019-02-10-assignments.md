## 一、考核结构 {#assessment}

| 组成 | 权重 | 权威证据 |
|---|---:|---|
| 六次个人作业 | 30% | ISE-A1 至 ISE-A6，每次 5 分 |
| 课堂表现、实验与同伴审查 | 10% | 教师按每次贡献质量评分，0–5 分 |
| 三人小组项目 | 40% | P0–P10 证据 Gate、仓库、发布与答辩 |

## 三、统一提交契约与 5 分量规 {#contract}

每次提交必须说明真实问题、来源、假设、候选方案、范围受控的产物、验证方法、原始结果、反例或限制、复现命令及重要 AI 使用。代码必须提供稳定 Commit Hash 或 Tag；截图和演示不能替代源码、测试和复现说明。

| 维度 | 分值 |
|---|---:|
| 问题、情境与方法选择 | 1.25 |
| 执行、产物质量与可复现性 | 1.50 |
| 分析、反例与适用边界 | 1.25 |
| 表达、反思与 AI 验证 | 1.00 |
| **每次满分** | **5.00** |

## 四、六次个人作业 {#individual-assignments}

### ISE-A1：问题与利益相关者证据简报

使用至少两类来源调查一个真实工作流，识别利益相关者、当前流程、痛点、约束、价值指标、非目标和适合一学期完成的范围；比较软件干预与至少一种非软件方案。提交证据台账、问题陈述、利益相关者图、正常/边界/滥用场景和未决假设。

### ISE-A2：领域模型与可检验规格

把 A1 工作流转化为领域词汇、流程或事件流、状态模型、数据字典和至少三个不变量。把一项重要规则表示为决策表、契约、断言或时序性质，给出违反示例并独立检查；说明数据来源、权限、保留、质量和隐私边界。

### ISE-A3：仓库调查与可复现构建

克隆并运行一个陌生仓库，记录环境、安装、构建和测试命令；定位入口、模块、持久化数据、外部接口、配置与关键依赖；重建一条端到端调用链；识别三个风险，并在 ADR 中比较处理其中一个风险的两种方案。观察事实与推断关系必须明确区分。

### ISE-A4：端到端垂直切片与自动验证

实现一个范围受控、可审查、可回滚的垂直切片，贯通需求、接口、授权、数据变化和用户反馈。提交任务契约、小型差异、适当的单元/集成/端到端测试、失败反馈、无障碍或 API 错误行为、审查发现和回滚路径。

### ISE-A5：质量与安全反例研究

选择一项重要的测试或安全主张。在改动系统前冻结环境、基线、Oracle、滥用场景或故障模型、阈值和停止条件；实施一个受控改进并使用同一证据流程复测，报告失败、被拒候选、副作用和适用边界。覆盖率或 Happy Path 通过不能单独构成充分证据。

### ISE-A6：可靠性与可观测性证据实验

定义具有代表性的负载或故障场景及可度量的可靠性主张；为关键路径增加观测，采集延迟、错误和资源基线；注入或复现一个故障，改进发现或恢复能力并重复测量。提交 Dashboard 或结构化日志、告警依据、回滚/恢复证据、剩余风险和精确复现步骤。

## 五、小组项目 Gate {#team-project}

| Gate | 周次 | 通过证据 |
|---|---:|---|
| P0–P2 | 2–4 | 有来源的问题、可追踪需求、领域/数据模型与异常 |
| P3–P4 | 6–9 | 架构候选、ADR、可运行原型和可证伪计划 |
| P5–P7 | 10–12 | 独立 Oracle、安全证据、可靠性/性能阈值 |
| P8–P9 | 13–14 | 可观测可回滚发布与跨组复现 |
| P10 | 15 | 一致的代码、证据、个人贡献、验收和路线图 |

## 六、AI 使用与学术诚信 {#ai-policy}

AI 和 Codex 可以调查仓库、提出候选方案、编写受控代码、补测试和分析失败日志；其输出只是候选，不是权威。学生必须披露重要使用，解释建议的采纳和拒绝理由，执行独立检查，保护密钥与个人数据并保留失败证据。伪造用户、访谈、Commit、测试、运行或结果均属学术不端。AI Tutor 不得释放当前计分任务的完整答案。

迟交或重新开放提交必须由教师在 `learn.spaiq.ai` 中记录许可；平台记录而不是非正式消息决定提交状态。
